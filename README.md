# 大麦抢票助手

在 Android 真机上，通过 adb 替你在**大麦 App** 里自动连点完成抢票：购买 → 确认 → 立即提交。走到支付宝收银台就停下，**付款永远由你自己完成**。

改写自 [prelearn-code/damai](https://github.com/prelearn-code/damai)「模式 0」，支持 REDMI K80，并增加了小米 15 的页面识别适配。

## ⚠️ 项目状态（2026-10-14，同一天同一台 K80 实战 6 场）

- ✅ **「不支持选座」的演出：已跑通。** 实测开售后 **5.3 秒**到达支付宝收银台，全程无风控、无异常弹窗。
- ⚠️ **「手动选座」的演出：已写代码，未实战。** 会停在选座页并点「确认选座」，但还没在真实开抢中验证过。
- ❌ **「一键下单 / 快速选座」的演出：未适配。** 这类是全新界面，脚本目前过不去。
- ⚠️ 有一个未修的 bug：确认页偶尔检测不到「立即提交」按钮。卡住超过 3 秒会自动保存截图，然后由你手动接手。

**结论**：抢「不支持选座」的演出，脚本能稳定从开售点跑到收银台。大麦有三种购票流程，界面完全不同，**抢之前先看详情页是哪一种**（见下方）。完整排查过程见 [`docs/实战复盘_2026-10-14.md`](docs/实战复盘_2026-10-14.md)。

## ⚖️ 使用前请知悉

- 自动化抢票**可能违反《大麦用户服务协议》**，可能导致账号被风控、限制购票甚至封号。实战中已多次触发大麦安全验证页。
- 本项目**不包含、也不接受**任何绕过风控、验证码、滑块、设备指纹的代码。小米 15 识别到安全验证会原地结束运行，交给你手动处理；K80 保留原来的返回一级行为。
- 仅供学习 Android UI 自动化，**禁止用于倒卖、黄牛或任何商业用途**，使用后果自负。

### macOS + 小米 15

已增加小米 15（24129PN74C）的 **1200×2670 竖屏**适配。运行时自动识别机型，
购买、确认和提交统一使用 `scripts/device_support.py` 中的固定点 `(930, 2502)`。
首击等待右下角实际出现「立即预订」「立即购票」或「立即购买」，随后持续点击固定点；正常票档和订单加载过程不再等待逐页识别放行。
后台 XML 用于异常接管：已确认购票流程中的详情骨架、空全屏转场和「尝试提交中」不会打断连点；未知页面、无效按钮、遮挡弹窗或读取失败仍暂停，前台进入支付宝立即停止。
启动时核验实际分辨率；运行中 XML 窗口信息能确认尺寸和方向时省去额外 ADB 查询，信息不足时仍回退实际查询。
「继续尝试」「努力刷新」「确认选座」均按当前按钮位置点击。小米 15 上，同一个「努力刷新」按钮持续可用时，重复点击的目标间隔为 150 毫秒；「继续尝试」仍为 1 秒。
K80 继续使用原来的 1440×3200 校准。

Mac 需要 Python 3.12、Android Platform-Tools 和 Xcode Command Line Tools（提供 `swiftc` 与系统 Vision OCR），终端中 `adb devices` 应能识别手机。
在仓库根目录安装依赖后执行预检。

```bash
python3.12 -m venv .venv-phone
.venv-phone/bin/python -m pip install -r requirements-phone.txt
.venv-phone/bin/python tools/precheck_K80.py
```

按钮检测还需要 [scrcpy v5.0.1 官方 server](https://github.com/Genymobile/scrcpy/releases/tag/v5.0.1)，下载到本地后启动时不联网：

```bash
mkdir -p artifacts/dependencies
curl -fL https://github.com/Genymobile/scrcpy/releases/download/v5.0.1/scrcpy-server-v5.0.1 -o artifacts/dependencies/scrcpy-server-v5.0.1
shasum -a 256 artifacts/dependencies/scrcpy-server-v5.0.1
```

SHA-256 应为 `764eb6f79811d5211fe9df341120882ba9994c7a61b897d7bf3fb662e53bc536`，程序启动时也会校验。
小米手机需自行开启「USB 调试」和「USB 调试（安全设置）」，程序不额外发送按键检查权限。
ADB 优先使用项目内对应操作系统的 Platform-Tools，其次从系统 PATH 查找。

在 App 内预选好场次、票档、观演人，保持目标详情页和亮屏。

在小米 15 上说「准备开抢，已经在详情页」时，直接运行固定入口。例：本次约定是今天 10:18 的李健合肥站：

```bash
.venv-phone/bin/python scripts/damai_mode0_K80.py --from-detail --show 李健 --show 合肥 --at 10:18
```

入口一次读取大麦详情页，核对演出标题、开售时间和「预填已完成」。匹配后自动启动预热、等待按钮变更，并在日志中记录核对结果。把本次已约定的信息作为参数，没指定的以当前页为准。字段缺失、有冲突或显示一键下单时，入口说明原因并退出。进入支付宝或明确识别到安全验证时停止，交由本人操作。小米 15 遇到未知页先暂停输入，再读取提示区域；即使页面 XML 里没有文字，屏幕出现「操作过于频繁，完成验证后可继续购票」也会以 `verification_required` 结束本次运行。

也可以手动传入完整开售时间启动原有入口。
以下运行入口会执行真实购票点击和提交订单。参数按 Mac 本地时间解释，用于日志和开售后 10 分钟截止；小米首击不靠系统时间放行。请至少提前一分钟启动，让 OCR 模型和视频流完成预热。

| 订单「立即提交」 | `(709, 2437) → (1132, 2580)` | 订单确认页，只读核对，未点击提交 |

票档「确定」在 XML 中没有文字，使用实测按钮 ID 加数量、总价控件识别，避免误认「已预约」。
这次完成了点位校准；虞书欣开售后的页面、实际提交及付款跳转仍待验证。
启动后先预热 OCR，并通过 ADB 和 scrcpy 读取右下角 828×148 区域的只读视频流，只处理最新帧、不录制视频。
「立即购票」「立即预订」已有小米原生字形模板，包含 2026-11-17 薛之谦场的购票字形，以及前一场预订初始帧和稳定帧，匹配阈值仍为 0.04。「立即购买」或未匹配的新字形交给预热后的 OCR 精确确认。未识别、空白或陈旧画面不放行，电脑到点也不会越过这项检查。
启动时确认大麦在前台，建立只向大麦应用 UID 投递触摸的连接。确认购买文案后直接发出首击，Android 在分发触摸时核对窗口归属。随后的连点目标间隔为 150 ms，每轮查询前台，发现支付宝就停止。如果在查询和触摸之间切到其他应用，Android 会拒绝投递，脚本立即停止。按钮帧在本场结束后保存。
小米 15 的定向触摸工具仅支持这台手机已验证的 Android 17（SDK 37）。开售前启动时校验工具的 SHA-256、Android 版本及大麦 UID，校验失败会退出。
两场共 239 帧回放中，207 张「已预约」零误触发，32 张购买文案全部走模板；旧版「立即购票」原图也独立回归。首帧本机匹配中位数约 1 ms；这是已保存样本的离线结果，不包含视频传输、前台检查和手机执行点击，也不保证未来未见字形同样命中。
正常流程中，明确的详情骨架或空全屏 Layout 只延续此前已确认的连点，不能用于初始放行或解除异常暂停；已知「尝试提交中」进度层也继续连点。居中空弹窗、额外未知窗口、禁用或屏幕外按钮仍暂停。

### 实战记录（自动保存）

小米 15 在 2026 年 11 月 17–19 日的六场实战、首次提交耗时及后续改动，见[小米 15 实战复盘](docs/小米15实战复盘.md)。

每次手动启动主程序，都会新建 `artifacts/run_<启动时间>/`，终端会打印实际路径，无需另开日志命令。

| 文件 | 内容 |
| --- | --- |
| `events.jsonl` | 按序记录每次命令发送、页面识别及耗时、前台应用变化、等待原因、状态决策和停止原因；包含毫秒时间及相对开售时间 |
| `console.log` | 终端输出和异常堆栈的副本 |
| `result.json` | 最终状态、计数、记录目录和写盘错误；正常结束、异常、Ctrl-C 均保存 |
| `frame_*.xml` | 页面或 XML 内容变化时，复用当次读取结果；同属未知页的空窗和 WebView 内容变化也保存，不额外读取手机 |
| `purchase_button_ready.png` / `button_frames/` | 文案确认帧及最近约 2 秒按钮帧；先保留内存引用，结束后写图和时间索引。未放行就结束也保存末尾帧，放行序号为 null，不生成 ready 图 |
| `initial.png` / `final.png` | 点击开始前、停止后的截图；启动距离连点不足 10 秒时跳过开场采集，并在日志中说明 |
| `stuck_*.xml` / `stuck_*.png` | 原有异常及卡页现场；小米 XML 复用触发时的快照，截图稍后采集 |

以 `events.jsonl` 为复盘时间线。小米 15 的 `input_dispatched` 表示 Android 已接受发给大麦的触摸，K80 的该事件表示命令已写入 ADB shell。判断大麦是否响应或成功提交订单还要看后续页面。
小米连续主流程的 `action=main` 表示固定点输入；附带页面状态来自后台观察，不能据此确定哪次输入是实际首次「立即提交」。
首击识别会记录以下事件，不能只拿最终一次 `match_ms` 当作完整反应时间：

| 事件 | 可复盘的信息 |
| --- | --- |
| `button_frame_processed` | 每次实际处理的帧序号、Mac 收帧时间、处理起止、最近模板差异、命中模板及来源、处理前后帧龄、放行或拒绝原因 |
| `button_ocr_started` / `button_ocr_finished` | 对应帧的 OCR 起止、耗时、识别原文及错误；之后即使因画面过期而丢弃，也保留这些事件 |
| `button_frame_skipped` | 识别前就过期的画面；各帧事件中的 `skipped_frames` 记录只处理最新帧导致的序号跳跃 |
| `purchase_button_ready` / `input_dispatched` | 放行时间、最终识别帧与输入起止时间。动态 OCR 学到的模板标为 `ocr_learned`。小米快速首击的 `input_guard=android_target_uid`、`query_ms=null` 表示由 Android 核对触摸目标，首击路径省去一次前台查询 |
| `snapshot_started` / `snapshot_skipped` / `dialog_snapshot` | 截图请求、忙/间隔/额度等跳过原因、实际采集开始、耗时和失败；重复跳过原因去重 |

小米持续未知页最多每 5 秒异步补一张截图，不再受全场三张上限限制；其它卡页截图仍保留原节流和额度。截图只开一个后台任务，图片与 XML 的采集时刻会分别留下证据。
点击事件通过内存队列交给后台写盘，关键 XML 不额外读取手机，不录屏。原有终端输出仍同步留档，异常截图也会占用手机资源，因此不能承诺零开销。
正常退出会等待事件落盘；强杀进程、断电或磁盘故障可能造成记录缺失。截图和 XML 含个人信息，只保存在已被 Git 忽略的本地 `artifacts/`。

## 大麦的三种购票流程（抢之前先判断）

在演出**详情页**上看标注，就能知道脚本支不支持：

| 详情页标注 | 流程 | 脚本支持情况 |
| --- | --- | --- |
| 「**不支持选座**」 | 详情页 → 票档面板 → 确认页 → 支付宝 | ✅ 已跑通 |
| 「可选座」且**没有**「一键下单」 | 详情页 → 票档面板 → **选座页** → 确认页 → 支付宝 | ⚠️ 已写代码，未实战 |
| 有「**一键下单，智能随机分配座位**」 | 详情页 → 快速选座面板 → 确认页 → 支付宝 | ❌ 未适配（演出方开通，无法关闭） |

脚本**不会**帮你选场次、票价、观演人，这些必须在开售前在大麦里手动预选好。

## 安全规则（代码里写死的）

绝不点支付宝付款｜绝不点「返回重新选购」｜只认文字是「继续尝试」的按钮（不靠控件 ID）｜认不出的弹窗不点｜小米 15 遇验证停机，K80 返回一级｜小米 15 的触摸绑定大麦 UID，K80 每次点击前查询前台｜屏幕分辨率必须完全一致，不一致直接退出。

## 第一次使用：配置

**1. 电脑装 Python 3.11+**：<https://www.python.org/downloads/>，安装时勾选 Add python.exe to PATH。

**2. 下载本项目**（不会 git 就用 GitHub 页面 Code → Download ZIP）：

```powershell
git clone https://github.com/yyxTheOracle/damai.git
cd damai
```

**3. 建虚拟环境 + 装依赖**（环境名必须是 `.venv-phone`，两个 bat 按这个名字找）：

```powershell
python -m venv .venv-phone
.venv-phone\Scripts\python.exe -m pip install -r requirements-phone.txt
```

**4. 下载 adb**（Google 官方 platform-tools），解压到项目根目录：

```powershell
Invoke-WebRequest https://dl.google.com/android/repository/platform-tools-latest-windows.zip -OutFile pt.zip
Expand-Archive pt.zip -DestinationPath . -Force
Remove-Item pt.zip
```

## 手机设置（REDMI K80 / HyperOS）

| 步骤 | 路径 | 为什么 |
| --- | --- | --- |
| 开 USB 调试 | 设置 → 更多设置 → 开发者选项 → USB 调试 | 电脑才能连手机 |
| **开 USB 调试（安全设置）** | 同上页，需登录小米账号 | **不开的话点击会被系统静默拦截**，预检查不出这项 |
| **分辨率改 WQHD+** | 设置 → 显示与亮度 → 屏幕分辨率 → WQHD+ | 默认 FHD+ 坐标会不对 |
| 充电时保持唤醒 | 开发者选项 → 充电时屏幕保持唤醒 | 防息屏 |

插数据线，手机弹「允许 USB 调试」时勾选**始终允许**。验证：`platform-tools\adb.exe devices` 应看到一行 `xxxxxxxx  device`。

## 抢票前：在大麦里手动设好

1. 打开目标演出**详情页**；
2. 点「去设置」，**选好实名观演人**（几个人买几张）；
3. 点「预约抢票」，**选好场次和票价**并提交；
4. 详情页显示「已设置本次抢票信息 → 已完成」即可；
5. 支付宝里钱够用。

## 每次抢票

开售前把手机停在该演出**详情页**（不要停在票档面板），然后二选一：

**A. 双击 `grab_K80.bat`**，按提示输入开售时间（`YYYY-MM-DD HH:MM:SS`，按电脑本地时间）。它会先自动预检，有 FAIL 就不启动。

**B. 命令行**：

```powershell
.venv-phone\Scripts\python.exe scripts\damai_mode0_K80.py "2026-10-20 12:00:00"
```

K80 保持开售前 2 秒进入点击阶段。小米 15 启动后准备视频流和后台检查，购买文案确认后开始固定点连点；
「已预约」不会放行首击，电脑到点也不替代文案确认。首次后台检查未通过或存在异常时仍暂停。
**运行期间不要碰手机**。

**开抢时你要盯：**
- 跳到**支付宝收银台** → 脚本自动停，你核对金额后自己付款（订单一般只留十几分钟）；
- 显示 `terminal_no_retry_option` → 你选的票档卖完了，手动换票档或等回流票；
- 弹出滑块/验证码 → 脚本不处理，自己拖；
- 页面几秒不动 → 可能卡住，直接手动接手。想停脚本：`Get-Process python | Stop-Process。

## 看懂运行结果

结束时输出的 JSON，最重要是 **`status`**：

| `status` | 意思 | 你该做什么 |
| --- | --- | --- |
| `alipay_reached` | ✅ 到了支付宝收银台 | 核对后自己付款 |
| `input_target_mismatch` | Android 拒绝将点击投递到当前窗口，本场已停 | 查看手机当前页面及日志中的前台应用 |
| `terminal_no_retry_option` | 票档卖完了 | 手动换票档 / 等回流票 |
| `timeout` | 开售后 10 分钟没成功 | 看现场文件找原因 |
| `error` | 程序出错 | 看 `worker_error` 字段 |

跑的时候每行一条过程日志：`state_probe`（页面/状态变了）、`heartbeat`（页面没变，每秒报一次）、`dialog_snapshot`/`stuck_page_snapshot`（自动保存的现场）。

**自动保存的现场**（在 `artifacts\`）：卡住时脚本会保存截图 + 界面 XML，只读不点击。
- `stuck_retry_dialog_*`「继续尝试」卡住；`stuck_sold_out_dialog_*` 库存不足；`stuck_unknown_dialog_*` 认不出的弹窗；`stuck_order_page_loading_*` 等开售后在确认页卡住超 3 秒。

## 适配其他手机

坐标按 1440×3200 校准。换手机：把 `scripts/damai_mode0_K80.py` 顶部的 `EXPECTED_SCREEN_SIZE` 改成你手机的实际分辨率，用 `tools\inspect_point_K80.py` 分别在详情页、票档面板确认 `MAIN_ACTION_POINT` 落在购买/确认按钮上。「继续尝试」「确认选座」的位置是实时读取的，不用校准。**改坐标时不要删掉分辨率校验。**

## 已知问题

- ❌ K80 确认页偶尔检测不到「立即提交」按钮，会空等。小米连续模式不再等待该文字才提交，但仍可能遇到拥挤或未知页面；卡住超 3 秒会自动保存现场。
- ❌ 「一键下单 / 快速选座」演出未适配。
- 🟡 大麦一更新，控件 ID / 页面结构可能失效。
